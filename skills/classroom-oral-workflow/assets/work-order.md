# 组稿工作单（执行者填写，不要求教师填表）

复制或沿用当前任务已有记录。本文件是空白调用模板，不是本轮已经完成的组稿。一个任务最多维护这一张工作单和一份正文；小任务可将它简化为正文后的教师附注。各岗只补自己负责的部分，直接复用上一岗输出，不重新研究已经确定的内容。

## 断点头：每次交接前更新

- 任务编号/版本、任务模式：
- 本单实际保存路径：由CURRENT_STATE.md指向此路径，不能只指空模板。
- 当前状态与暂停原因：进行中 / 等待新对话续接 / 待教师评价 / 关键缺证阻塞 / 已结束。
- S0—S6逐岗状态及实质结果位置：未开始、进行中、完成、待教师；“完成”必须有正文/决定/依据，不以填表替代。
- 当前正文的身份与位置：输入旧稿 / 本轮草稿 / 核后稿 / 教师认可稿；旧稿存在不等于本轮S4完成。
- 下一步与执行者：从哪岗做哪件事，完成后停在哪里。
- 输入版本：本任务、认可纲、所用Skill和外部蒸馏的路径与实际提交；不只写main。
- 已认可/不得改范围与授权边界：
- 未决问题、是否阻塞、允许采用的有限处理：
- 本次已保存的工作与未保存的变化：有真实本地工作区才核其状态；不声称读过用户电脑。

恢复时先核最新main并固定同一提交，依CURRENT_STATE找到本单，读实质结果后再判断完成状态。main有新提交时只比对相关任务变化，不把“有新提交”当整套研究作废。必须保留的旧聊天正文、关键来源与判断先写入任务文件，不能写“见上次聊天”代替交接。

权限优先依教师最新明确指令，历史反馈不得膨胀成制作授权。无新依据不重做已完成工序；发现错误可定向退回并写明原因。提交正文和工作单后再更新当前指针，回读同一提交检查目标存在。跨对话实际执行、同会话读回、静态链接检查分别报告，不把后两者称为冷启动实测。真实恢复时简记读到的版本、恢复状态、实际动作及是否出现返工/越权；不新增一套测试平台。

## 可直接使用的调用语

### 组稿

读取skills/classroom-oral-workflow/SKILL.md，按流程为【知识点或已认可大纲中的位置】形成一个完整的课堂口播单元。沿用课程对象和已认可范围，自动取所需材料，实际调用适合的蒸馏写法；连续完成研究、选材、编排、写作、自检和有必要的返修。先给口播正文，后附关键来源与短说明。不要只交新计划，不做PPT、Word、PDF，不自动扩成整讲。

### 依反馈局部修改

读取同一Skill，按已有工作单和这条反馈修订：【教师反馈】。先定位失效工序，只改受影响内容和必要承接；保留已认可段落。使用原来源与技能，不再全库调研。交一份修后正文和简短实际差异，不另造平行稿。

### 跨对话恢复

先核最新main，按START_HERE.md、CURRENT_STATE.md、SKILL.md读取当前实际工作单。仅凭文件恢复目标、逐岗状态、正文身份、认可边界和下一步，读完实质材料后从断点继续。不要重做已完成工序，不以空模板当进度，不靠旧聊天补缺。记录实际恢复结果；本轮授权不扩展到配套制作。

### Codex接续

读取同一Skill和当前工作单，只完成其中分配给你的阶段。核Pro已经给出的事实依据和实际口播，列明确问题并在授权范围内定点修订；重要材料或核心讲法的改变交Pro判断。不要重新规划课程、全篇润色或导出未授权文件。若工作单尚无Pro内容裁决，先交具体查证结果和候选，不独立改定核心蓝图。
